Incident Response Lifecycle

Incident Response (IR) is the structured process for handling a security breach. SANS Institute provides the industry standard framework.

The 6 Steps of Incident Response

1. Preparation
This happens before an attack. It involves having a response plan, backups, and monitoring tools (like SIEM) already in place.

2. Identification (Detection)
This is the detection phase. The SIEM triggers an alert or a user reports suspicious activity. You must determine if this is a false positive or a real incident.

3. Containment (The Most Critical Step)
This is about stopping the damage.
Short-term containment: Disconnect the affected machine from the network by unplugging the cable or disabling the switch port.
Long-term containment: Apply temporary firewall rules or change passwords to prevent the attacker from moving further.

4. Eradication
Removing the root cause. This includes deleting malware, uninstalling suspicious services, and patching the vulnerability that allowed the attacker in.

5. Recovery
Restoring the system to normal operations. Data is restored from clean backups. Systems are patched and reconnected to the network.

6. Lessons Learned
A meeting is held after the incident. The team discusses what went wrong, what was done well, and how to improve the security posture for the future.

SOC Analyst Role in IR
As a Level 1 analyst, you are primarily responsible for Detection and Initial Containment.
